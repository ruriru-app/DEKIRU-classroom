# RuRiRu Town LEVEL 3 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan in the existing isolated checkout.

**Goal:** Add the agreed speech-driven LEVEL 3 activity to the existing RuRiRu Town map.

**Architecture:** Keep LEVEL 2 assets and files intact. A pure model handles fixed unit expressions, half-block roads, destinations and shortest-distance hints. A speech controller owns microphone/synthesis exclusion; the page handles setup, confirmation and explicit execution.

**Tech Stack:** Buildless HTML/CSS/JavaScript, Web Speech API, Node tests, Playwright for browser checks.

**Spec:** The approved in-chat LEVEL 3 design, captured below.

## Global Constraints

- Large map left, recording and recognized sentence below; A–N starts, one-sentence optional hint, destinations on the right.
- Select destination from the map or list with confirmation; recording requires both start and goal.
- Try speaking without a hint first. Accept only the four agreed expression forms; route optimality does not affect language acceptance. Execute only when the child presses 動かす.
- Rejected speech enables the optional hint button; reveal no sentence automatically. The hint gives only the next sentence for the current position and heading.
- Whole-block distance is relative to the current position; just a little bit is half a block. Turns rotate 90° in place anywhere. Never travel through buildings or off the map.
- You can see it on your right/left indicates that relative side without movement. Complete only when the configured goal is on that side at its roadside arrival position.
- Recognizer must end before synthesis. Ignore stale recognition events, wait after playback, then resume recognition only if the activity is still active.
- Reuse original character animations and sounds and the approved LEVEL 3 map. No links to teacher/admin/top pages (AGENTS.md).
- Browser recognition may need network and microphone permission; physical classroom recognition must be checked on school tablets.

## Review Focus

1. Correct grammar/number normalization without accepting missing words or multiple commands.
2. Valid language still accepted when it is a detour or physical movement is blocked.
3. Hint recalculation, relative left/right, and every start/destination combination.
4. Delayed recognition/synthesis callbacks after reset, page hide, destination change or repeated playback.
5. Tablet layout, facility hit areas, dialogs, unsupported speech and no navigation outside the activity.
